## 一、随堂练习（每节点动手小题）

> 每题先自己做，再对参考答案。做不动就回看对应讲次，不要跳过 gate。

### C1 · 高效 & 强化微调原理（含显存 gate）

**练习 C1-1（gate 核心）**：关掉 Agent，手算 7B 模型在三种方式下的微调显存量级，填表：

| 方式 | 你的估算 | 参考量级 | 推荐卡 |
|---|---|---|---|
| 全量微调（FP16） | ___ | 60GB | A100(40GB)×2 |
| LoRA（FP16） | ___ | 16GB | RTX 4090 |
| QLoRA（INT4/NF4） | ___ | 6GB | RTX 3060 |

- 参考答案与自查：三档量级来自讲 01《模型微调概览与硬件选取》。关键结论是同一个 7B，全量 60GB 对比 QLoRA INT4 6GB，差约 10 倍。手算时记得在表值上再预留 20%+ 缓冲（激活值、优化器状态、batch 都会额外吃显存），别卡着表值买卡/租卡。
<!--src:A; ref:讲01《模型微调概览与硬件选取》显存表; look:career-sprint#C1-->

**练习 C1-2**：给三个场景各选一种微调方法并写一句理由：(a) 手里只有一张 24GB 的 4090，要给客服模型注入话术；(b) 有 A100×8 集群、要把金融专家模型效果做到极致；(c) 要让模型"回答更安全、更合规"。

- 参考答案：(a) QLoRA，单卡消费级、显存最省，注入领域风格够用；(b) 全量微调，数据量大、多卡集群、追极致效果；(c) 这是"学偏好"不是"学知识"，SFT 灌数据学不会，应上强化微调（DPO 首选）。自查：分不清"学知识 / 学偏好"就是 C1 最大的坎，学知识用 SFT（LoRA/QLoRA），学偏好用 PPO/DPO/GRPO。
<!--src:A; ref:讲01《模型微调概览与硬件选取》+RLHF/DPO; look:career-sprint#C1-->

**练习 C1-3**：一句话说清 LoRA 和 QLoRA 的关系。

- 参考答案：QLoRA = 4bit 量化底模 + LoRA 增量。LoRA 只训注入的低秩矩阵但仍要加载完整底模，QLoRA 在此之上把底模量化成 4bit(NF4) 再训 LoRA，把"加载底模"这块显存砍到最低（讲 01 QLoRA 原理，65B 案例：LoRA 130GB → QLoRA 48GB）。
<!--src:A; ref:讲01《QLoRA微调原理》; look:career-sprint#C1-->

### C2 · 数据集获取与自主构建

**练习 C2-1**：把下面这条"数据"改成合格的 alpaca 单条格式，并指出原始问题。
原始：`{"instruction": "请把这句话翻译成英文：今天天气很好", "output": ""}`

- 参考答案：output 为空是硬伤（模型回答必填）。应改为 `{"instruction": "请把这句话翻译成英文", "input": "今天天气很好", "output": "The weather is nice today."}`。待翻译内容属于 input，不该塞进 instruction；input 无内容时留 `""` 而非省略（讲 02 私有数据集构建）。
<!--src:A; ref:讲02《私有数据集构建》alpaca格式; look:career-sprint#C2-->

**练习 C2-2**：你要从一批私有 PDF 造 500 条微调数据，写出你的质量把关顺序。

- 参考答案：先小批量生成 → 抽样人工读 20 条校验方向对不对 → 去重 → 清洗（删错误标注 / 空 output / 格式损坏）→ 字段对齐（instruction/input/output 不错位）→ 脱敏与版权确认 → 格式校验通过 → 再批量放大。核心红线：少量高质量 > 大量低质量，方向错了训练越久离目标越远（讲 02 微调数据概览）。
<!--src:A; ref:讲02《微调数据概览》; look:career-sprint#C2-->

### C3 · 借助 Llama-Factory 高效微调

**练习 C3-1**：你的自定义数据集放好了，`--dataset my_sql` 却报"找不到数据集"，列出排查三步。

- 参考答案：(1) 确认已在 `dataset_info.json` 里注册了 `my_sql` 这个条目，`--dataset` 认的是注册名不是文件名；(2) 确认 `--dataset_dir` 指向对、文件路径真实存在；(3) 确认 JSON 是合法的 list 结构、字段名没拼错（讲 03 LoRA 微调）。
<!--src:A; ref:讲03《LoRA微调》dataset_info注册; look:career-sprint#C3-->

**练习 C3-2**：给 Qwen2.5 跑 LoRA，写出 rank/alpha/dropout/target 的稳妥起手值并各说一句为什么。

- 参考答案：`lora_rank=8~32`（小任务 8，注入较多领域知识可到 32/64）、`lora_alpha=16`（经验取 rank 的 1~2 倍）、`lora_dropout=0`（数据足可 0，数据少改 0.05 防过拟合）、`lora_target=all`（不确定就全部线性层；显存紧时优先 q_proj/v_proj）。`template` 必须与模型家族一致（Qwen→qwen），template 错配是"答非所问 / 重复生成"的头号成因（讲 03）。
- 注：这里的优先注入位置写 q_proj/v_proj，依据 LoRA 原论文 Table 5（有限预算下 Wq+Wv 最优）。课件正文口径是 q_proj/k_proj，二者差异见面试题 Q2 脚注，面试时可主动点破以显示读过原论文。
<!--src:A; ref:讲03《LoRA微调》配参 + LoRA原论文 arXiv:2106.09685 Table5; look:career-sprint#C3-->

**练习 C3-3**：训练启动就 CUDA out of memory，写出从代价最小到最大的降显存顺序。

- 参考答案：(1) 降 batch（`per_device_train_batch_size` 调小，用 `gradient_accumulation_steps` 补等效 batch）→ (2) 降精度换方法（LoRA→QLoRA，INT8→INT4）→ (3) 降序列长度 `cutoff_len` → (4) 开 DeepSpeed ZeRO / 参数卸载到 CPU → (5) 还不够才加卡/换更大卡。别一 OOM 就想买 A100（讲 03 Windows QLoRA + 排错分诊树）。
<!--src:A; ref:讲03《Windows QLoRA》降显存分诊; look:career-sprint#C3-->

### C4 · 微调 & 蒸馏应用实战

**练习 C4-1**：微调 DeepSeek-R1 这类推理模型，长思维链数据怎么组织？

- 参考答案：把推理过程拼进 `<think>...</think>` 再接最终答案，output 同时含"推理链 + 答案"；并按约 75%:25% 的比例混入推理数据与非推理数据（对应 R1 第二轮 SFT 的约 60 万推理样本 + 约 20 万非推理样本，共 80 万条）。掺约 1/4 非推理数据，是为了防止模型退化成只会长篇推理、丢了正常对话能力（讲 04 DeepSeek-R1 微调）。
<!--src:A; ref:讲04《DeepSeek-R1微调》长思维链数据配比; look:career-sprint#C4-->

**练习 C4-2**：微调后模型开始"重复生成 / 车轱辘话"，先怀疑什么？

- 参考答案：先查 chat template 与模型是否匹配、EOS 结束符是否配对，再查数据质量。不要第一反应就狂调 epoch 和学习率，那大概率是 template 错配（讲 04 + 排错分诊树 D 分支）。
<!--src:A; ref:讲04 + 微调失效分诊树 D 分支; look:career-sprint#C4-->

### C5 · 企业级微调实战（分布式）

**练习 C5-1**：单机多卡能跑，上多机就卡住/超时，排查方向？

- 参考答案：先用 `torchrun`(DDP) 在单节点多卡验证能跑通，再上 `deepspeed`；检查 NCCL 环境、各节点 world_size/rank/master 地址一致、`ddp_timeout` 设够大（讲 05 分布式金融专家模型）。
<!--src:A; ref:讲05《分布式金融专家模型》; look:career-sprint#C5-->

**练习 C5-2（阶段交付物）**：把 C1–C4 的成果整理成一份可写进简历的「微调实战记录」，自查是否包含五要素。

- 参考答案 / 验收清单：① 显存估算表（目标模型 × 精度 × 方法）；② 方法选型理由（为什么 LoRA/QLoRA、为什么这个框架）；③ 训练配置（rank/alpha/template/量化设置/关键超参）；④ 领域评测指标（执行准确率 / 召回 / perplexity / reward 均值，用留出集算）；⑤ 过拟合排查（train vs val loss，取 val 最低点 checkpoint）。缺任一项都不算合格的求职级记录（讲 05 + 讲 04 验收）。

## 二、误区自查

> 逐条对照。命中任一条，说明对应知识点还没掌握，按提示回看。

1. **如果你以为"数据越多微调效果越好"** → 你还没掌握"质量 > 规模"这条最关键的红线。决定效果的是质量分布不是总量，1000 条高质量胜过 10 万条噪声。回看讲 02 微调数据概览。
<!--src:A; ref:讲02《微调数据概览》; look:career-sprint#C2-->
2. **如果你以为"想让模型更安全/更懂礼貌就多灌 SFT 数据"** → 你还没分清"学知识 vs 学偏好"。安全、合规、偏好是 SFT 学不会的，要上 DPO 等强化微调。回看讲 01 RLHF/DPO 详解。
<!--src:A; ref:讲01《RLHF/DPO 详解》; look:career-sprint#C1-->
3. **如果你以为"量化完精度不够可以再转回 FP16 补回来"** → 你还没理解量化是有损单向。只能高精度→低精度，量化后信息已丢，精度不够要从源头提 bit（INT4→INT8）或不量化。回看讲 01 QLoRA / 量化技术。
<!--src:A; ref:讲01《QLoRA/量化技术》; look:career-sprint#C1-->
4. **如果你以为"loss 降了 / 能跑通就是微调成功"** → 你还没掌握验收。loss 降可能已过拟合，必须用没训过的留出集对比前后、查 val loss 是否回升、给出可复算的领域指标。回看讲 04 / 讲 03 验收环节。
<!--src:A; ref:讲04/讲03 验收环节; look:career-sprint#C4-->
5. **如果你以为"LoRA 比全量省显存是因为不用加载底模"** → 你记反了。LoRA 只训低秩增量，但仍要加载完整底模；真正把加载底模显存砍下去的是 QLoRA 的 4bit 量化。回看讲 01 LoRA/QLoRA 原理。
<!--src:A; ref:讲01《LoRA/QLoRA 原理》; look:career-sprint#C1-->
6. **如果你以为"有偏好数据就该训个奖励模型再跑 PPO"** → 你还没掌握 DPO 的价值。有成对偏好数据直接上 DPO，免奖励模型、免多模型同载，成本最低。专门训奖励模型再 PPO 是多此一举。回看讲 01 DPO 详解。
<!--src:A; ref:讲01《DPO 详解》; look:career-sprint#C1-->
7. **如果你以为"微调后模型重复生成是模型不行"** → 你还没掌握排错分诊。十有八九是 chat template 与模型家族错配或 EOS 没配对，先修 template 再谈其它。回看讲 03 / 排错分诊树。
<!--src:A; ref:讲03 + 排错分诊树; look:career-sprint#C3-->
8. **如果你以为"蒸馏就是让小模型完全等于大模型"** → 你还没理解蒸馏是有损迁移。目标是"接近且成本可控"，而且教师/种子数据方向错了，蒸馏会把错误**放大**，必须先小批量校验方向。回看讲 04 R1 蒸馏 / 讲 01 蒸馏技术。
<!--src:A; ref:讲04 R1 蒸馏 / 讲01 蒸馏技术; look:career-sprint#C4-->
9. **如果你以为"rank 拉到 128+ 效果一定更好"** → 你还没掌握 LoRA 配参。rank 太大参数暴涨、显存吃紧还易过拟合，多数领域任务 8~32 就够。回看讲 01 LoRA 原理 / 讲 03。
<!--src:A; ref:讲01 LoRA 原理 / 讲03; look:career-sprint#C1-->
10. **如果你以为"一 OOM 就得换 A100"** → 你还没掌握降显存顺序。先降 batch、换 QLoRA、降 cutoff_len、开 ZeRO offload，加卡是最后一步。回看讲 03 排错。
<!--src:A; ref:讲03 排错分诊; look:career-sprint#C3-->

## 三、迁移挑战

> 换个场景，用同一套方法。能迁移才算真掌握，这是"懂了没"的核心判据。

**迁移 1（换任务：NL2SQL → 医疗问答）**：你在 C3 用 Llama-Factory 给 Qwen2.5 微调过 NL2SQL，验收指标是 SQL 执行准确率。现在换成"医疗领域问答"微调，你的**数据格式、验收指标、过拟合防线**分别怎么改？
- 参考答案：数据仍走 alpaca 指令对，但若要教推理则用含推理链的 CoT 格式；验收指标从"SQL 执行准确率"换成"领域测试集准确率 + 困惑度 perplexity"（Embedding 类子任务看检索命中/召回，如"心脏病"能否召回"冠心病"）；过拟合防线不变，用留出集看 train vs val loss、val 回升就取早停 checkpoint。方法论（先算显存→选方法→配 LoRA→注册数据→训练→验收）整套复用，只换指标口径（讲 03 + 讲 04 PEFT 医疗微调）。
<!--src:A; ref:讲03 + 讲04《PEFT 医疗领域微调》; look:career-sprint#C3-->

**迁移 2（换目标：SFT → 强化微调）**：同样是"提升数学推理"，如果只有"最终答案对/错"这种稀疏奖励、没有成对偏好数据，你会选 PPO / DPO / GRPO 哪个？如果改成"有大量人工标注的成对偏好回答"呢？
- 参考答案：只有"答案对/错"的稀疏可验证奖励、要练推理 → 选 **GRPO**（组内多次采样相对比较、可用规则奖励、DeepSeek-R1 主路径）；有现成成对偏好数据、只想稳稳对齐 → 选 **DPO**（免奖励模型、单一损失、训练稳、省算力）。两种情形都必须先有 SFT 模型打底，不能拿 base 模型直接上强化微调（讲 01 GRPO/DPO + 讲 04 R1 GRPO 实战）。
<!--src:A; ref:讲01 GRPO/DPO + 讲04 R1 GRPO 实战; look:career-sprint#C4-->

**迁移 3（换规模：单卡 → 企业分布式）**：你在 4090 上用 QLoRA 跑通了 7B。现在要在公司 A100×16 上微调一个金融专家大模型，**框架、并行方案、显存优化**怎么升级？
- 参考答案：框架从 Llama-Factory 单卡转到 PEFT+DeepSpeed（或仍用 Llama-Factory 接 DeepSpeed 后端）；并行用 DeepSpeed，单节点多卡先 `torchrun`(DDP) 验通再上多机；显存优化用 ZeRO 分级（ZeRO-1/2/3）+ 参数卸载 offload 到 CPU。数据量足、要极致效果可从 QLoRA 升到 LoRA 甚至全量。方法链不变，换的是"扛规模"的基建（讲 05 分布式微调）。
<!--src:A; ref:讲05《分布式微调》; look:career-sprint#C5-->

## 四、排错挑战

> 下面是一份真实感的 Llama-Factory LoRA 微调启动配置（新手常踩的写法），跑起来撞了一连串问题。
> 请先自己找出所有毛病，再看答案。

```bash
# train_qwen_lora.sh —— 目标：单张 24GB 4090 上给 Qwen2.5-7B 做 LoRA 微调
llamafactory-cli train \
  --model_name_or_path Qwen2.5-7B-Instruct \
  --stage sft \
  --do_train \
  --finetuning_type lora \
  --lora_rank 128 \
  --lora_alpha 8 \
  --template llama3 \    
  --dataset my_medical \
  --per_device_train_batch_size 8 \
  --cutoff_len 4096 \
  --report_to none \
  --output_dir ./out
```

**参考答案**（每条按【症状】→【根因】→【修法】三段拆解）：

1. **【症状】**①命令报参数错误、`--dataset` 之后的参数像没传进去。**【根因】**：`--template llama3 \` 的续行反斜杠 `\` 后面多了空格，导致命令在这里断掉、后面参数没进程序。**【修法】**：删掉每个续行 `\` 后的所有空格/字符。
2. **【症状】**②提示"找不到数据集 my_medical"。**【根因】**：自定义数据集没在 `dataset_info.json` 注册，`--dataset` 认的是注册名不是文件名。**【修法】**：先在 `dataset_info.json` 注册 `my_medical` 条目、确认 `--dataset_dir` 指向对、文件为合法 JSON list，再重跑。
3. **【症状】**③好不容易跑起来立刻 CUDA out of memory。**【根因】**：24GB 卡上，7B LoRA(FP16)≈16GB 本已吃紧，`per_device_train_batch_size=8` + `cutoff_len=4096` 直接爆；且 `lora_rank=128` 让可训练参数暴涨。**【修法】**：按代价从小到大，batch 降到 1~2 用 `gradient_accumulation_steps` 补等效 batch、`cutoff_len` 降到 1024~2048、`finetuning_type` 从 lora 换 qlora（4bit），rank 回落到 8~32。
4. **【症状】**④勉强训完，模型答非所问、不停重复。**【根因】**：`--template llama3` 与 Qwen 家族错配（这是重复生成的头号成因）；另 `lora_alpha 8` 配 `rank 128` 缩放严重失衡。**【修法】**：`--template qwen`；按 alpha 取 rank 的 1~2 倍改（如 rank 16 / alpha 16~32）。

修正后的关键行应是：`--finetuning_type qlora`、`--lora_rank 16`、`--lora_alpha 32`、`--template qwen`、`--per_device_train_batch_size 1`、`--gradient_accumulation_steps 8`、`--cutoff_len 1024`，且所有续行 `\` 后无空格，`my_medical` 已注册。（综合讲 03 + 微调训练失效分诊树：环境 / 数据集 / OOM / template / 命令续行五类症状）

## 五、面试自测（15 题 · 面试向加重）

> 每题给「考察点 / 答题要点 / 两层追问链」。追问链是面试官会怎么一层层往深挖，
> 你要能扛住第二层追问，才算真掌握而不是背了个结论。刷题时先捂住答案自己讲一遍。

**Q1 · LoRA 的原理是什么？A、B 两个矩阵怎么初始化，为什么？**
- 考察点：低秩分解的本质与训练稳定性设计。
- 答题要点：LoRA 冻结原权重 W₀，在旁路注入两个低秩矩阵 B·A（W = W₀ + (α/r)·BA），只训 A、B。**A 用高斯分布初始化、B 初始化为零**，这样训练初期 BA=0、增量为零，不破坏预训练权重，从原始能力平滑起步。（讲 01 LoRA 微调原理）
- 追问链：① 如果 A、B 都用高斯初始化会怎样？→ 初始增量非零，起步就扰动预训练权重，训练不稳；② 推理时 LoRA 增量能不能合并进原权重、对推理延迟有无影响？→ 能，把 BA 合并回 W₀ 后推理零额外开销，这是 LoRA 相对 Adapter 的一大优势。
<!--src:A; ref:讲01《LoRA 微调原理》; look:career-sprint#C1-->

**Q2 · lora_rank 和 lora_alpha 怎么选？target_modules 注入到哪些层？**
- 考察点：LoRA 配参的工程判断，不是背默认值。
- 答题要点：rank 控制可训练参数量与适配能力，小任务 8、标准 16/32、注入较多领域知识可到 64；alpha 是缩放系数，经验取 rank 的 1~2 倍（更新幅度按 α/r 缩放）；target 不确定就用 all（全部线性层），显存/参数紧张时优先 q_proj、v_proj。（讲 01 + 讲 03）
- 追问链：① rank 拉到 128 会有什么风险？→ 参数暴涨、显存吃紧、易过拟合，多数领域任务 8~32 足够；② 课件里 GPT-3 实验为什么说预算有限时优先只注入 Wq、Wk？→ 课件口径是"有限参数预算下作用于 query、key 投影效果最好"。见下方脚注。
- 脚注：课件正文写"有限预算下 Wq、Wk 最优"，但 LoRA 原论文（arXiv:2106.09685）§7.1 与 Table 5 的实测结论是"adapting both Wq and Wv yields the best result"，即有限预算下 query+value 组合最优、单放 Wq 或 Wk 明显更差。面试遇到这个点，可主动点破课件与原论文的差异、以 Wq+Wv 作答，显示你读过原论文。
<!--src:A; ref:讲01+讲03 配参；LoRA原论文 arXiv:2106.09685 §7.1 Table5（课件口径差异见脚注）; look:career-sprint#C1-->

**Q3 · QLoRA 是什么？NF4 量化和双量化分别解决什么？**
- 考察点：QLoRA 的三件套是否真理解，而非只知"省显存"。
- 答题要点：QLoRA = 4bit 量化底模 + LoRA 增量。NF4 是针对正态分布设计的 4bit 非线性量化（把标准正态的分位数等分映射，中心密集、尾部稀疏），因为神经网络权重通常近似高斯分布，NF4 比普通 INT4 量化误差更小；双量化 = 对量化时产生的量化常数（缩放因子等）再做一次量化，进一步省显存；计算时用 `compute_dtype=bf16` 反量化保精度。（讲 01 QLoRA 微调原理）
- 追问链：① 为什么 NF4 要针对正态分布设计？→ 权重服从高斯分布，用分位数量化让码点落在密集区，最小化量化误差；② QLoRA 忘了设 compute_dtype、全程 4bit 参与计算会怎样？→ 精度损失过大、训练质量崩，计算必须反量化到 bf16。
<!--src:A; ref:讲01《QLoRA 微调原理》; look:career-sprint#C1-->

**Q4 · QLoRA 为什么能省这么多显存？举个量级。**
- 考察点：能不能给出可信的量级证据，而不是空谈。
- 答题要点：省的主要是"加载底模"这块。课件以 65B 为例：全量微调 500GB+、LoRA 130GB（仍需加载完整底模）、QLoRA 48GB（4bit 量化底模 + LoRA 增量），单张 48GB 卡即可微调 65B、24GB 消费级卡可微调 33B。权重 FP16 130GB 量化到 4bit 约 32.5GB。（讲 01 QLoRA 原理）
- 追问链：① QLoRA 省显存的代价是什么？→ 量化有损，精度略降、且是不可逆的高→低；训练/推理有反量化开销；② 分页优化器在这里起什么作用？→ 把优化器状态在显存不足时溢出到 CPU，配合 4bit 权重让大模型在单卡跑得动。
<!--src:A; ref:讲01《QLoRA 原理》65B案例; look:career-sprint#C1-->

**Q5 · 手算：7B 模型全量、LoRA、QLoRA INT4 微调各需多少显存？**
- 考察点：显存估算是微调岗的硬门槛，答不出直接减分。
- 答题要点：量级上，全量(FP16)≈60GB（A100 40GB×2）、LoRA(FP16)≈16GB（4090）、QLoRA(INT4)≈6GB（3060/4080）。同一 7B 全量 vs QLoRA 差约 10 倍。实际要在表值上预留 20%+ 缓冲（激活值、优化器状态、batch 会额外占）。（讲 01 模型微调概览与硬件选取）
- 追问链：① 为什么全量比 LoRA 贵这么多？→ 全量要为所有参数存梯度和优化器状态（Adam 每参约存两份动量），LoRA 只为极少量低秩增量存这些；② AMP 混合精度为什么反而占用更高？→ 训练时要保留一份 FP32 权重副本，7B AMP 约 120GB，比纯 FP16 更吃显存。
<!--src:A; ref:讲01《模型微调概览与硬件选取》显存表; look:career-sprint#C1-->

**Q6 · SFT 和强化微调分别学什么？什么时候必须上强化微调？**
- 考察点：微调最根本的分野，学知识 vs 学偏好。
- 答题要点：SFT 本质是"最大化给定输入下输出标准答案的概率"，是静态映射、学知识/风格/格式；强化微调学"偏好"，更安全、更合规、按相对好坏优化、提升多步推理。当出现"要更安全/合偏好""同一问题多种合理答案要按相对好坏优化""要练数学/代码/因果推理"时才上，且必须先有 SFT 模型打底。（讲 01 RLHF/PPO 详解）
- 追问链：① 为什么强化微调一定要 SFT 打底、不能拿 base 直接跑？→ base 输出分布太散，策略无从收敛，PPO/GRPO 的策略模型、DPO 的初始模型都从 SFT 模型出发；② SFT 数据量和偏好数据量通常差多少？→ SFT 常 GB 级/百万样本，偏好数据 MB 级/万样本，但决定效果的是质量分布不是总量。
<!--src:A; ref:讲01《RLHF/PPO 详解》; look:career-sprint#C1-->

**Q7 · RLHF-PPO 需要同时维护哪几个模型？各干什么？**
- 考察点：PPO 的成本劣势从架构上讲清。
- 答题要点：四个，策略模型 Actor（待训练目标）、参考模型 Reference（冻结，约束分布不跑偏）、奖励模型 Reward（给完整回答打分）、价值/评论家模型 Critic（估计状态价值算优势）。四模型同载导致显存翻倍、训练不稳、调参难，是 PPO 最大成本劣势。（讲 01 PPO / RLHF 详解）
- 追问链：① Reference 模型的作用具体是什么？→ 用 KL 散度约束策略别偏离 SFT 模型太远，防止为刷高 reward 而胡说（reward hacking）；② 奖励模型怎么训练出来的？→ 用同一问题的成对回答（chosen/rejected）、序列分类头 + pairwise 对比损失训练，让 chosen 得分高于 rejected。
<!--src:A; ref:讲01《PPO / RLHF 详解》; look:career-sprint#C1-->

**Q8 · DPO 为什么不需要奖励模型？和 PPO 比省在哪？**
- 考察点：DPO 的核心卖点与适用前提。
- 答题要点：DPO 把 RLHF 的"训奖励模型 + PPO 优化"两阶段合成单一损失，直接用成对偏好数据（chosen/rejected）优化，隐式带 KL 约束，不显式训奖励模型、不多模型同载，训练稳、省算力。前提是要有高质量成对偏好数据（chosen 明显优于 rejected）。（讲 01 DPO 详解 + 讲 03 DPO 微调 Qwen2.5）
- 追问链：① DPO 相比在线的 PPO 有什么固有短板？→ DPO 是 offline、用固定偏好数据训练，存在偏好数据分布与当前策略漂移、分布外挤压问题，不能像 on-policy 那样持续自我改进（这一点课件未展开，依据 DPO 原论文 arXiv:2305.18290 及后续在线/离线对齐研究）；② 只有"答案对/错"没有成对偏好数据，还能用 DPO 吗？→ 不合适，这类稀疏可验证奖励的推理任务更适合 GRPO 规则奖励。
<!--src:B; ref:讲01 DPO详解+讲03；DPO原论文 arXiv:2305.18290（offline偏好分布漂移为其固有短板，一手来源核实）; look:career-sprint#C1-->

**Q9 · GRPO 相比 PPO 改了什么？组内相对优势怎么算？**
- 考察点：当下最热的 GRPO，答不上会显得没跟进前沿。
- 答题要点：GRPO 去掉了 PPO 的价值/评论家模型，改用"对同一 prompt 采样一组答案（如 8 个）做组内比较"来估计优势：优势 ≈ (该答案奖励 − 组内奖励均值) / 组内奖励标准差。好处：省掉评论家训练开销、组内相对比较降方差、样本效率高，适合稀疏/最终奖励、推理对齐、多目标平衡，是 DeepSeek-R1 的主路径。代价是一次要生成多个答案、推理开销增加。（讲 01 GRPO 详解 + 讲 04 R1 论文精读与 GRPO 实战）
- 追问链：① 去掉评论家为什么可行、不会不稳吗？→ 用组内均值当基线替代价值函数估计的基线，同样能降方差、还免了额外一个网络；② GRPO 的奖励从哪来？→ 可训奖励模型，也常用规则/可验证奖励（如正确性 + 输出格式），推理任务的"答案对不对"就是天然可验证奖励。
<!--src:A; ref:讲01 GRPO详解 + 讲04 R1 GRPO 实战; look:career-sprint#C4-->

**Q10 · PPO / DPO / GRPO 三选一，你的默认决策是什么？**
- 考察点：不是背区别，而是能做工程决策。
- 答题要点：默认 DPO（有成对偏好数据、只想稳稳对齐、成本最低）；要练推理 / 只有稀疏最终奖励 / 要多目标（格式+正确性+安全）→ GRPO；已有历史 RLHF 基建、团队熟 PPO、要在线精细控奖励 → PPO（新项目不建议首选 PPO，最费卡最不稳）。三者都要回查显存表确认多模型同载装得下、且都要 SFT 打底。（讲 01 各强化微调详解）
- 追问链：① 为什么新项目不建议起 PPO？→ 要同载 Actor/Ref/Reward/Critic 四模型，显存翻倍、训练最不稳、调参最难；② 有成对偏好数据还专门训奖励模型再 PPO，问题在哪？→ 多此一举，DPO 免奖励模型直接用偏好对就够。
<!--src:A; ref:讲01 各强化微调详解; look:career-sprint#C1-->

**Q11 · 微调数据集有哪些格式？怎么按目标选？**
- 考察点：数据格式选型 = 选你要培养的能力。
- 答题要点：指令-回复对 alpaca（instruction/input/output）练指令跟随/领域问答；多轮加 history 练上下文连贯；CoT（output 含推理过程+答案）练推理，如 R1 蒸馏；偏好数据（同问多答+排序）做 DPO/PPO 对齐；工具调用轨迹练 function calling。Llama-Factory 系支持 alpaca 与 sharegpt 两种。（讲 02 微调数据概览 + 私有数据集构建）
- 追问链：① 要训推理能力却用普通指令对（output 只有答案没推理）会怎样？→ 训不出 CoT，推理能力得靠含推理链的数据；② input 字段什么时候留空、能不能把它塞进 instruction？→ 无输入时留 `""`，不能塞进 instruction，字段错位会教坏模型。
<!--src:A; ref:讲02《微调数据概览》+私有数据集构建; look:career-sprint#C2-->

**Q12 · 微调数据的质量红线有哪些？为什么说数据是天花板？**
- 考察点：能不能把"数据决定成败"讲成可执行的红线。
- 答题要点：微调天花板是数据质量，算法再先进救不回脏数据。红线：质量 > 规模（少量高质量胜大量低质量）、instruction/input/output 字段语义对齐不错位、去重、清洗（删错标注/空 output/损坏样本）、格式与框架模板匹配、脱敏合规、方向先小批量校验再放大。方向错了微调会固化、蒸馏会放大。（讲 02 微调数据概览 + 私有数据集构建）
- 追问链：① 为什么不去重会出问题？→ 重复样本让模型过拟合到少数模式，测试集直接崩；② 蒸馏时数据方向错了为什么比普通微调更危险？→ 蒸馏是学生复用教师知识，教师/种子方向错会被成倍放大。
<!--src:A; ref:讲02《微调数据概览》+私有数据集构建; look:career-sprint#C2-->

**Q13 · 微调推理模型（如 R1）要注意什么？长思维链怎么处理？**
- 考察点：推理模型微调这个 2025–2026 高频新考点。
- 答题要点：把推理过程拼进 `<think>...</think>` 再接最终答案、末尾配好 EOS；按约 75%:25% 混入推理数据与非推理数据（R1 第二轮 SFT 约 60 万推理 + 约 20 万非推理，共 80 万），掺约 1/4 非推理数据是为了防止模型退化成只会长篇推理；评测时按需过滤掉思考段只看最终答案；训练/推理注意 enable_thinking / reasoning_effort 之类的开关。（讲 04 DeepSeek-R1 微调实战）
- 追问链：① 不混非推理数据会怎样？→ 模型可能退化、遇到简单对话也硬输出长思维链，通用能力下降；② 评测推理模型时为什么要过滤思考段？→ 思考段是中间过程，验收要看最终答案质量，混进去会干扰指标。
<!--src:A; ref:讲04《DeepSeek-R1 微调实战》长思维链配比; look:career-sprint#C4-->

**Q14 · 蒸馏有哪几种类型？闭源 API 当教师只能选哪种？R1 蒸馏是怎么做的？**
- 考察点：蒸馏类型与现实约束的匹配。
- 答题要点：响应级（学教师答案文本，只需教师能生成，最常用）、分布级（学 teacher logits/概率分布，需白盒、存储大）、特征级（学中间层激活/注意力，最精细、需白盒）。教师是闭源 API 拿不到 logits，只能走响应级。R1 蒸馏 = 用 R1/大模型对领域问题生成带 CoT 推理链的答案，组成 SFT 数据微调小模型，属响应级 + CoT 蒸馏。（讲 01 量化与蒸馏技术 + 讲 04 R1 蒸馏）
- 追问链：① 综合蒸馏和分步蒸馏怎么选？→ 有高质量领域数据用分步（先领域微调再蒸馏，效果更好但方向错会放大），数据一般/求快用综合；② 蒸馏完怎么验收？→ 在留出领域题上对比学生 vs 教师答案质量，确认能力真迁移，别形似神不似。
<!--src:A; ref:讲01 量化与蒸馏技术 + 讲04 R1 蒸馏; look:career-sprint#C4-->

**Q15 · 微调完的模型要量化上线，GPTQ / AWQ / GGUF / bitsandbytes 怎么选？PTQ 和 QAT 区别？**
- 考察点：量化选型的四层次分清 + 部署环境决策。
- 答题要点：先分清算法（GPTQ/AWQ/NF4）、精度（INT4/INT8，W4A16 指权重4位激活16位）、量化框架、推理框架四层。按部署环境选：CPU/Mac → GGUF+llama.cpp；GPU 生产要稳 → GPTQ+GPTQModel（W4A16）；精度优先 → AWQ（激活感知，同 INT4 精度通常更好）；只是训练省显存 → bitsandbytes NF4（就是 QLoRA 那套）。默认档 W4A16。PTQ = 训练后一次性量化（默认、最简单）；QAT = 训练时就模拟量化（精度更好但要重训，INT4 掉点严重才上）。（讲 01 量化技术 + 讲 05 企业级微调模型量化；工具部署选型经官方文档核实：llama.cpp/GGUF、AutoGPTQ、AWQ 论文 arXiv:2306.00978）
- 追问链：① 生产 GPU 推理为什么不建议用 bitsandbytes？→ 它适合实验/训练省显存，生产 GPU 推理 GPTQ/AWQ 更稳更快；② 无脑冲 INT4/W3A16 求最小体积的风险？→ 高压缩比对长文本生成掉点明显，量化完必须在留出集比量化前后指标再上线。

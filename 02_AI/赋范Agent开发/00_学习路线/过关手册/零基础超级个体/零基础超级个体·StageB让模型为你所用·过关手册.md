## 一、随堂练习

### 练习 1：写出最小的在线调用脚本，并打印本次 token 数

要求：用 DeepSeek 平台的 `deepseek-chat` 模型，问它"你是谁？"，拿到回复后把本次消耗的 token 数打印出来。API Key 必须从环境变量读，不许硬编码。

【参考答案】

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com"
)

response = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role": "user", "content": "你是谁？"}]
)

print(response.choices[0].message.content)
print(f"输入 Token: {response.usage.prompt_tokens}")
print(f"输出 Token: {response.usage.completion_tokens}")
print(f"总计 Token: {response.usage.total_tokens}")
```

【自查要点】三个字段名是否逐字写对：`prompt_tokens`（输入）、`completion_tokens`（输出）、`total_tokens`（总计）。回复内容取自 `response.choices[0].message.content`，注意是 `message` 不是 `delta`（那是流式才用的）。Key 通过 `os.getenv()` 读，代码里不出现真实密钥。

### 练习 2：不调 API，手工估算一段中文的 token 数

给你这句话：`用一句话解释什么是人工智能`（14 个汉字）。按课件的快速估算法，它大概是多少 token？再说说为什么"估算"和 API 实际返回的数字会有出入。

【参考答案】课件的中文快速估算公式是"字数 × 0.5 ～ 1"，所以 14 字大约落在 7 ～ 14 token 区间。之所以只能给区间，是因为真实切分由各家分词器决定：课件实测口径里，DeepSeek 中文约"1 字 ≈ 0.6 token"，Qwen 约"1.5～1.8 字 ≈ 1 token"，同一句话在不同模型上 token 数不同。要精确只能看 API 返回的 `usage`，或用对应模型的官方分词器本地算。

【自查要点】你有没有把估算当成精确值？记住估算是拍脑袋定预算用的，账要按 `response.usage` 走。中文 1 token 约等于 1～2 个汉字，取决于分词算法。

### 练习 4：手算一次调用花多少钱（关底徽章预演）

按课件的 DeepSeek V3.2 定价：输入 ¥2.0／百万 token（缓存未命中）、输出 ¥3.0／百万 token。假设某次对话输入 1000 token、输出 500 token，全部缓存未命中，这轮花多少钱？

【参考答案】输入费 = 1000 ÷ 1,000,000 × 2.0 = ¥0.002；输出费 = 500 ÷ 1,000,000 × 3.0 = ¥0.0015；合计 ¥0.0035。关键是记住计费以"百万 token"为单位，且输入、输出分开计价、输出单价更高。若这 1000 输入 token 走的是缓存命中，输入单价降到 ¥0.2／百万，输入费只要 ¥0.0002。

【自查要点】有没有把输入输出用同一个单价算？有没有漏掉"每百万"这个分母？这道题就是关底闭卷手算题的原型，练到能脱稿写出算式。

## 二、误区自查

以下六条，每条先判断对错，再看纠正。

1. 「按次数计费的第三方平台，就跟 token 无关了。」错。课件明确：几乎所有官方平台都按 token 计费；部分第三方中转按次数或套餐展示，但底层仍基于 token 消耗，只是展示方式不同。
<!--src:A; ref:讲次《大模型基础入门（在线API调用与本地部署）·大模型在线API接入基础入门实战》必要的基础知识：什么是Token-->

2. 「输入和输出的 token 一个价。」错。输入（prompt）和输出（completion）通常分开计价，输出 token 价格更高。算账要分开算。

3. 「换个平台要重写一套代码。」错。凡是声称兼容 OpenAI 格式的平台，从技术上只需改两处：`base_url` 和 `model`。DeepSeek、阿里百炼、智谱、OpenRouter 都吃这套。

4. 「DeepSeek 地址末尾加 `/v1` 里的 v1 是模型版本 V1。」错。课件专门点破：这个 `v1` 与模型版本无关，只是为了兼容 OpenAI 的 URL 格式，加不加效果一样。

5. 「DeepSeek-V3 激活才 37B，本地显存需求跟一个 37B 模型差不多。」错。这是新手最容易犯的错。MoE 模型显存必须按总参数量算：DeepSeek-V3 总参数 671B，FP16 下约需 1.3TB，所有专家权重都得加载进内存等待被调用。
<!--src:A; ref:讲次《大模型基础入门（在线API调用与本地部署）·大模型本地部署基础入门》3.3.1 静态显存 / 3.1.4 Dense与MoE-->

6. 「模型宣传支持 128K 上下文，我就能一直聊到 128K。」错。KV Cache 随上下文长度线性增长，实际能用多长取决于显存余量。课件给的判断法：可用上下文长度 ≈（总显存 − 模型显存）÷ 每 1K token 的 KV Cache 大小。
<!--src:A; ref:讲次《大模型基础入门（在线API调用与本地部署）·大模型本地部署基础入门》3.3.2 动态显存：KV Cache-->

### 挑战 1：把 DeepSeek 脚本搬到阿里百炼

你已经有一段能跑通的 DeepSeek 调用脚本（见随堂练习 1）。现在要改成调用阿里云百炼的通义千问，其他逻辑一律不动。你要改哪几处、改成什么？

【参考答案】只改两处。`base_url` 改成百炼北京地域地址：


`model` 从 `deepseek-chat` 换成 `qwen-plus`，Key 换成百炼的 `DASHSCOPE_API_KEY`。这就是"兼容 OpenAI 格式"的红利：学会读一个平台的文档，等于学会所有平台的接入。

### 挑战 2：24GB 的 4090 想跑 70B，怎么办

手上一张 RTX 4090（24GB 显存），想在本机跑一个 70B 模型。FP16 原始权重要 140GB，明显装不下。给出一条可行路线并说明取舍。

【参考答案】走量化 + 混合卸载。70B 做 INT4 量化后权重约 35GB，仍超过 24GB，所以选 GGUF 格式：它允许把一部分层放显存、剩余层留在系统内存由 CPU 算，显存不够内存来凑。代价是速度会从纯 GPU 的约 50 t/s 掉到 3～5 t/s，但至少能跑。若显存够装满，则该用 AWQ/GPTQ 这类纯 GPU 格式换更快的速度（但它们装不下就直接 OOM）。INT4 相对 FP16 困惑度大约只升 5%，日常对话几乎无感。
<!--src:A; ref:讲次《大模型基础入门（在线API调用与本地部署）·大模型本地部署基础入门》7.1 量化基础 / 7.2.2 GGUF-->

## 四、排错挑战

【症状】你照着课件写了 DeepSeek 调用脚本，`base_url` 和 Key 都确认没问题，一运行却报 400 Bad Request，提示模型不存在：

```python
response = client.chat.completions.create(
    model="deepseek-v3.2",   # 报错这里
    messages=[{"role": "user", "content": "你好"}]
)
```

【根因】把"底层模型版本号"当成了"API 调用名"。课件里 DeepSeek 的两个可调用模型名是 `deepseek-chat`（非思考、快）和 `deepseek-reasoner`（思考模式、输出推理链），二者底层都已升级到 DeepSeek-V3.2。`deepseek-v3.2` 是底层模型代号，不是接口里能直接填的调用名，所以服务端找不到。

【修法】把 `model` 改回官方调用名：日常对话用 `deepseek-chat`，要可解释的推理过程用 `deepseek-reasoner`。排这类错的通用动作：去官方文档的 Models & Pricing 板块核对调用名，别凭印象拼。顺带记住排查三件套——先看完整错误信息（`str(e)`），再核对 API Key 有没有多余空格、`base_url` 有没有写错斜杠、`model` 名大小写是否正确。

## 五、面试自测

### 1. Token 是什么？为什么平台按 token 计费，而不是按字符或请求次数？

【考察点】对最底层计费单位的理解。
【答题要点】Token 是大模型处理文本的基本单位，可理解为"文本片段"；模型不是按字符或单词处理，而是把文本切成一个个 token。按 token 计费是因为它直接对应模型的计算量，比字符/次数更能反映真实成本。英文约 1 token ≈ 4 字符或 0.75 单词，中文约 1 token ≈ 1～2 个汉字。
【追问】输入 token 和输出 token 一个价吗？（答：分开计价，输出 token 价格通常更高。）
<!--src:A; ref:讲次《大模型基础入门（在线API调用与本地部署）·大模型在线API接入基础入门实战》必要的基础知识：什么是Token-->

### 2. 兼容 OpenAI 格式的平台之间，切换一次要改哪些东西？

【考察点】能不能抓住"两行代码"的本质。
【答题要点】只需改 `base_url`（API 基础地址）和 `model`（模型调用名），配合对应平台的 Key。比如 DeepSeek 用 `api.deepseek.com` + `deepseek-chat`，百炼用 `dashscope.aliyuncs.com/compatible-mode/v1` + `qwen-plus`，智谱用 `open.bigmodel.cn/api/paas/v4/` + `glm-4`。调用方法 `chat.completions.create()` 和 `messages` 结构都不变。
【追问】DeepSeek 的 `base_url` 末尾加不加 `/v1` 有区别吗？（答：没有；那个 `v1` 与模型版本无关，只为兼容 OpenAI 的 URL 格式。）
<!--src:A; ref:讲次《大模型基础入门（在线API调用与本地部署）·大模型在线API接入基础入门实战》2.7.1 / 2.5.3-->

### 3. API-Key 承担哪些职能？为什么绝对不能硬编码进代码？

【考察点】密钥安全意识。
【答题要点】API-Key 通常以 `sk-` 或 `ak-` 开头、长度 40～60 字符，承担三个职能：身份认证（证明你是谁）、权限控制（能用哪些模型、速率限制）、费用归属（所有调用都计入这个账户）。一旦泄露，他人能冒用你的身份并恶意消耗你的余额。所以绝不能硬编码、不能提交到 Git、不能在日志明文输出。
【追问】那正确的存法是什么？（答：用环境变量，把 Key 放 `.env` 文件、用 `os.getenv()` 读，并把 `.env` 加进 `.gitignore`。）
<!--src:A; ref:讲次《大模型基础入门（在线API调用与本地部署）·大模型在线API接入基础入门实战》API-Key：数字身份证与安全红线-->

### 4. 流式输出是怎么回事？开启后取内容用哪个字段？

【考察点】流式的实现细节。
【答题要点】设 `stream=True`，模型边生成边返回，用户能看到打字机效果，还能中途终止省成本。返回值是一个迭代器，逐块遍历，每块的增量内容在 `chunk.choices[0].delta.content`。
【追问】为什么这里是 `delta` 而不是 `message`？（答：流式返回的是增量片段 `delta`，要自己累加拼成完整文本；非流式一次性返回完整内容才用 `message.content`。）
<!--src:A; ref:讲次《大模型基础入门（在线API调用与本地部署）·大模型在线API接入基础入门实战》3.5 流式输出-->

### 5. 遇到 401 和 429，处理策略有什么不同？

【考察点】错误分类与重试设计。
【答题要点】401（AuthenticationError，Key 无效/过期）不该重试，重试也没意义，应直接返回提示让人去检查配置。429（RateLimitError，请求过快）应等待后重试，用指数退避：等待时间逐次翻倍。网络类错误（APIConnectionError）可短暂等待后重试。
【追问】指数退避的等待时间序列是怎样的？（答：`2 ** attempt`，即第 1 次等 1 秒、第 2 次 2 秒、第 3 次 4 秒，避免高峰期持续加压。）
<!--src:A; ref:讲次《大模型基础入门（在线API调用与本地部署）·大模型在线API接入基础入门实战》3.6.1 常见错误类型与分类捕获-->

### 6. 在线 API 和本地部署，成本结构差在哪？什么时候该选本地？

【考察点】能不能把成本账讲清楚（关底能力）。
【答题要点】在线 API 是按量付费、边际成本随 token 走、零硬件投入、免运维，适合起步和波动流量；本地部署是前期硬件/显存投入大、边际成本趋近于零、数据不出境、可离线，适合高频稳定用量或对数据隐私敏感的场景。课件建议新手先从在线 API（如 DeepSeek）起步，跑不动本地模型时也能只用在线 API 完成目标。
【追问】哪些情况明显该上本地？（答：数据不能出境、需要离线、调用量大到摊薄硬件成本，或想自定义/微调模型时。）
<!--src:A; ref:讲次《大模型基础入门（在线API调用与本地部署）·大模型本地部署基础入门》3.3.4 显存不够怎么办 / 在线API章节-->

### 7. 静态显存怎么估？Qwen3-14B 的 FP16 大概要多少？

【考察点】显存速算公式。
【答题要点】公式：静态显存(GB) ≈ 参数量(B) × 每参数比特数 ÷ 8。FP16 每参数 2 字节，Qwen3-14B 约 14 × 2 = 28GB。同理 Qwen3-8B 约 16GB、Qwen3-32B 约 64GB。
【追问】为什么实际占用还要再加一点？（答：要在公式结果上加约 1～2GB 修正系数，用于 CUDA 内核开销、显存碎片和临时缓冲区；而且推理时 KV Cache 还会随上下文继续吃显存。）
<!--src:A; ref:讲次《大模型基础入门（在线API调用与本地部署）·大模型本地部署基础入门》3.3.1 静态显存-->

### 8. 为什么 MoE 模型的显存必须按总参数量算？

【考察点】MoE 部署的核心矛盾。
【答题要点】MoE 每次推理只激活一小部分专家（如 DeepSeek-V3 总 671B、每次只激活约 37B），所以算得快、接近 37B Dense 模型的速度；但门控网络在每一层都可能选到不同专家，你无法提前知道哪些会被用到，所有专家权重都必须先加载进内存待命。因此显存/内存需求由总参数量决定：DeepSeek-V3 FP16 约需 1.3TB。
【追问】那 MoE 本地部署怎么破？（答：Expert Offloading——把共享专家和当前激活的路由专家放显存，大量休眠专家放 CPU 内存；对 MoE 来说内存容量常比显存更关键，llama.cpp、KTransformers 这类框架就是干这个调度的。）
<!--src:A; ref:讲次《大模型基础入门（在线API调用与本地部署）·大模型本地部署基础入门》3.1.4 Dense与MoE / 3.3.1 MoE显存陷阱-->

### 9. INT4 为什么被称作本地部署的"甜点"精度？

【考察点】量化的性价比判断。
【答题要点】量化是把高精度浮点数映射成低精度整数换显存。INT4 每参数 0.5 字节，把 70B 从 FP16 的 140GB 压到约 35GB，双卡 3090 就能跑；而质量损失很小，Qwen3-8B 从 FP16 困惑度 5.12 到 INT4 约 5.38，只升约 5%，日常对话几乎无感。在显存节省和效果保持之间取得了最佳平衡。
【追问】所有任务都能随便压到更低吗？（答：不能。困惑度只是必要条件不是充分条件；编程、数学、强逻辑任务 4-bit 是底线，再往 3-bit 压准确率会明显掉。PPL 变化 1～3% 可视为无损，>10% 就严重有损。）
<!--src:A; ref:讲次《大模型基础入门（在线API调用与本地部署）·大模型本地部署基础入门》7.1 精度与量化基础-->

### 10. Ollama 和 vLLM 该怎么选？

【考察点】本地推理方案选型。
【答题要点】Ollama 定位开发者工具/本地实验，底层 llama.cpp + GGUF，一条命令起步，硬件要求极低，适合单用户或少量并发；vLLM 定位企业级 API 服务，底层 PagedAttention 优化 KV Cache，支持数百并发、吞吐更高，但配置更复杂、要数据中心级 GPU。简单原则：个人研究、调 Prompt、跑非生产应用用 Ollama；要对外提供高并发 API 用 vLLM。
【追问】用 Ollama 跑完怎么确认没退化成 CPU 推理？（答：`ollama ps` 看 `PROCESSOR` 列是否为 `100% GPU`，一旦发生 CPU 卸载推理会极慢。）

## 一、随堂练习（动手小题）

### E1 · 部署实战：AI HR 数字员工「小慧」
> 来源：项目 `README.md` 快速开始 / `AGENTS.md` 启动与验证标准 / `run.sh` / `backend/src/server.ts`

**练习 E1-1｜一键起前后端并做健康自检**
你刚把小慧项目拉到本机。写出把它跑起来的最省事命令，以及启动后用来确认后端活着的那条 `curl`，并说出返回里你要盯的三个字段。

- 【参考答案】
  ```bash
  # 项目根目录一条命令起前后端（缺 node_modules 会自动 npm install）
  ./run.sh
  # 起来后验证后端健康
  curl http://localhost:8788/api/health
  # 期望：{"ok":true,"service":"ff-xiaohui-hr-backend","mode":"mock",...}
  ```
  要盯的三个字段：`ok` 为 `true`（服务起来了）、`service` 为 `ff-xiaohui-hr-backend`（确认是这个后端）、`mode` 为 `mock`（默认引擎模式，零外部依赖）。
- 【自查要点】`run.sh` 会从 8788（后端）和 5190（前端）向上扫第一个空闲端口，所以端口被占也不用手动改；它还会把前后端都绑到 `0.0.0.0` 并注入局域网地址，同一 Wi-Fi 下手机也能开。启动后终端会打印「本机访问」和「局域网访问」两个 URL。
  <!--src:A; ref:code:run.sh; code:backend/src/server.ts-->

**练习 E1-2｜背下部署验收清单**
小慧的 `AGENTS.md` 给了一份「部署完成的验证标准（Agent 自检清单）」。凭记忆写出其中至少 4 条（默认 mock 模式下能逐项核对的）。

- 【参考答案】任写 4 条即可：
  1. `./run.sh` 启动后终端打印「本机访问」与「局域网访问」两个 URL 且无报错；
  2. 对后端 `/api/health` 发 `curl`，返回 JSON 且 `ok:true`、`mode:"mock"`；
  3. 浏览器打开前端 URL，落地页正常渲染，能进 `/app` 看到侧栏六职能；
  4. 对后端 `/api/recruitment` 发 `curl`，返回非空场景总览 JSON；
  5. 在总控调度台用「普通员工」发「导出全公司花名册」被拦截，切「HR 主管」再发被放行。
- 【自查要点】E1 的徽章要求是你**亲手逐项勾**这份清单（不让 Agent 代填），再手写一页部署复盘，里面至少写清 1 个你自己排掉的错误。清单每一条都能用命令或界面直接看到结果，不是靠感觉。
  <!--src:A; ref:code:AGENTS.md 部署完成的验证标准-->

**练习 E1-3｜权限拦截的现场演示**
进 `/app` 总控调度台，用「普通员工」身份发一句「导出全公司花名册」，会看到什么？切成「HR 主管」再发同一句呢？为什么是这个差别？

- 【参考答案】用「普通员工」发，四步时间线走到「权限校验」那一步会标红、结果变成「已拦截」，并提示可切换到 HR 主管重试；换成「HR 主管」再发，四步全绿，返回「已校验全员数据导出权限 → 生成全公司花名册（在职 / 部门 / 职级 / 入职日期），导出动作已写入审计留痕」。差别在于这条任务的允许身份名单只有 `hr`：全公司花名册含全员个人信息，按《个人信息保护法》最小必要原则，只有 HR 主管有全员数据导出权限。
- 【自查要点】权限判定就是一句 `task.allow.includes(role)`：命中放行、不命中拦截并拉起红色拦截卡。政策自助问答（如「年假没休完怎么办」）三档身份都允许，招聘 / 入职 / 培训 / 绩效多是「部门负责人 + HR 主管」，花名册导出和 HR 月报才是 HR 主管独享。
  <!--src:A; ref:code:frontend/src/modules/RouterConsole.tsx; backend/data/router.json-->

**练习 E1-4｜说清双引擎：默认跑哪个、real 怎么才生效**
小慧号称「双引擎」。默认跑的是哪个引擎？想切到 real 真调 Agent，后端判定「就绪」要满足什么条件？没配好会怎样？

- 【参考答案】默认跑 `mock`（回放 `backend/data/*.json` 里录得的脱敏企业数据，零外部依赖）。切 real 要 `BRAIN_MODE=real`，且后端 `useReal()` 复核通过，即 `openclawAvailable()` 为真，需要 `~/.openclaw-hr` 目录存在且里面有 `env.sh`（profile 与密钥就绪）。没配好时 `run.sh` 会打印降级提示并自动以 mock 启动，`/api/health` 里 `mode` 仍是 `mock`，核心演示照跑不误。
- 【自查要点】判定就绪只看两样：`profilePresent`（`~/.openclaw-hr` 在不在）和 `envConfigured`（`env.sh` 在不在），不强校验 `openclaw` 这个可执行文件本身（它由 PATH 提供）。密钥一律只进 `~/.openclaw-hr/env.sh`，绝不写进代码或提交 git。
  <!--src:A; ref:code:backend/src/openclaw.ts; backend/src/server.ts-->

### E2 · 自选第二个敏捷项目（支线）
> 来源：`README.md` 让你的 Agent 帮你跑起来 / 敏捷项目清单（mini-chatgpt / fufan-llm-playground / autopilot）

**练习 E2-1｜换个项目，第一句话怎么对 Agent 说**
你在敏捷项目清单里挑了第二个项目（比如 mini-chatgpt），它也带 `AGENTS.md`。为了复刻 E1 那套「让 Agent 部署、你来验收」的流程，你在项目根目录对 Agent 发的第一句话应该包含哪几件事？

- 【参考答案】一句话要把整条部署路线交代清楚：让它先**读 AGENTS.md**、**检查我的环境**、**向我要齐所需的外部服务凭证**、然后**完成安装 / 配置 / 启动**、最后**按「部署完成的验证标准」逐项自检并汇报结果**。这正是 README「让你的 Agent 帮你跑起来」给的那句提示词的结构。
- 【自查要点】关键不是背那句话，而是记住它覆盖的五个动作：读手册 → 查环境 → 要凭证 → 装配起 → 自检。第二个项目和第一个的区别只在数据和外部服务，方法一模一样。
  <!--src:A; ref:code:README.md 让你的 Agent 帮你跑起来-->

**练习 E2-2｜判断一个项目能不能走「Agent 读手册部署」这条路**
拿到一个陌生项目，怎么快速判断它适不适合用「Agent 读 AGENTS.md 一键部署」这条路线？看哪几样东西？

- 【参考答案】看根目录有没有这三样：① `AGENTS.md`（给 AI Agent 读的操作手册，命令优先、精确到 flag）；② `CLAUDE.md`（Claude Code 的入口，通常一行 `@AGENTS.md` 指向它）；③ README 里有没有「外部服务准备」表和一份可逐项核对的「验证标准 / 自检清单」。三样齐全，Agent 就能自己走完环境检查 → 要凭证 → 安装配置 → 启动 → 自检的全流程。
- 【自查要点】小慧的 `CLAUDE.md` 内容就只有一行 `@AGENTS.md`：Claude Code 读到它就转去读 AGENTS.md，人类可读版看 README，需求细节看 docs/PRD.md，三者分工明确。没有这套文档的项目，你就得回到手工按 README 一步步来。

## 二、误区自查（照镜子）

> 读法：如果你心里认同左边那句话，说明你还没真正掌握右边那件事，去回看对应节点。

1. **如果你以为「部署跑通就等于让 Agent 跑一遍 ./run.sh 就完事」** ，说明你还没抓住 E1 的验收在哪：徽章要求是你亲手逐项勾 AGENTS.md 的「部署完成的验证标准」并手写一页复盘，不是让 Agent 代填。回看 zero-to-builder#E1 的深潜验收说明。

2. **如果你以为「默认就是 real 模式在真调大模型」** ，说明你还没搞清双引擎：默认是 `mock`，回放 `backend/data/*.json` 的录得数据、零外部依赖；real 要 `BRAIN_MODE=real` 且 `~/.openclaw-hr` + `env.sh` 就绪才生效。回看 zero-to-builder#E1，重点看 `backend/src/openclaw.ts` 的 `openclawAvailable()`。

3. **如果你以为「三档身份是登录鉴权、能防真人越权」** ，说明你把演示开关当成了真实认证。这三档身份是前端可自由切换的权限演示开关，项目本身没有注册 / 登录 / 会话鉴权。回看 zero-to-builder#E1，看 docs/PRD.md 第 5 章范围之外。

4. **如果你以为「花名册导出被拦是代码写死不让导」** ，说明你没看懂权限判定：拦不拦只看这条任务的允许身份名单里有没有当前身份，切成 HR 主管同一句就放行。背后的依据是《个人信息保护法》最小必要原则。回看 zero-to-builder#E1，看 `RouterConsole.tsx` 的 `allow` 与 `buildSteps`。

5. **如果你以为「real 模式把用户输入拼进 shell 命令很危险、这项目有注入漏洞」** ，说明你没读全防护：agent id 是数据文件里的受控常量、不来自用户输入，用户消息经 `JSON.stringify` 转义后再传给 `-m`，而且全局串行队列一次只跑一个、90 秒超时 SIGKILL。回看 zero-to-builder#E1，看 `backend/src/openclaw.ts` 的 `runNow`。

6. **如果你以为「第二个项目还要从头学一套部署方法」** ，说明你没意识到 E1 练的是一套可复用的验收流程：读手册 → 查环境 → 要凭证 → 装配起 → 自检，换项目只换数据和外部服务。回看 zero-to-builder#E2，方法同 E1。

## 三、迁移挑战（换个场景用同样方法）

**迁移挑战 1｜把小慧的三档权限模型搬到你自己的一个小工具**
小慧用一个「允许身份名单」给每类操作分权限。假设你有一个个人小工具，里面有「查看本人笔记」「导出全部笔记」「批量删除」三类操作，请照小慧的思路，为每类操作设计一个允许名单（自定义几档身份），并说清一次操作被拦下来时，界面该给用户什么反馈。

- 【怎么算过关】① 每类操作都有明确的允许名单，敏感操作（导出全部 / 批量删除）名单最窄；② 判定逻辑能一句话说清，就是「当前身份在不在这条操作的允许名单里」；③ 被拦时不只是报错，还要像小慧那样告诉用户「缺哪个权限、切成哪个身份能重试」。能说清「为什么导出全部要收窄」就说明你把最小必要原则迁移过来了。
  <!--src:A; ref:code:frontend/src/modules/RouterConsole.tsx-->

**迁移挑战 2｜把「Agent 读 AGENTS.md 部署」变成一门远程装机的小服务**
很多人有现成开源项目但装不明白。请把 E1 学到的部署流程，设计成你给别人远程装机接活的标准动作：从对方把项目发你，到你交付「能打开的地址 + 自检结果」，中间分几步、每步交付什么。

- 【怎么算过关】能给出一条可复用的动作线：先确认项目根有没有 AGENTS.md / README 外部服务表 → 让 Agent 读手册查环境 → 向对方要齐外部服务凭证（且提醒凭证只进 `env.sh` 或 `.env`、不进代码不进 git）→ 一键起 → 逐项过验证标准 → 把自检截图和访问地址交付。能指出「默认先走 mock / 零外部依赖那条最稳」，说明你抓住了「课堂直播零翻车」这条设计带给接活的稳妥打法。

## 四、排错挑战（给你一段带病的配置，修好它）

一位同学没用 `./run.sh`，而是手动分开起前后端。他的后端正常起在默认端口，前端也起来了，但**页面一片空白、发任何任务都没反应**。他手动改过的前端环境变量文件长这样：

```bash
# frontend/.env（手动单起前端时用）
VITE_API_BASE=http://localhost:8787
```

后端这边用的是默认端口，`server.ts` 里写着：

```ts
const PORT = Number(process.env.PORT) || 8788;
```

请找出问题并修好。

- 【症状】前端页面空白、请求全部失败；后端本身健康（对 8788 端口的 `/api/health` 发 `curl` 能返回 `ok:true`），但前端就是连不上后端，控制台是一堆请求错误。
- 【根因】前端 `VITE_API_BASE` 指向了 `8787`，而后端手动起在默认的 `8788`（`server.ts` 里 `PORT || 8788`）。前端把所有 API 都打到一个没人监听的端口上，自然全部失败、页面空白。`8787` 是项目早期模板里的旧默认值，后来已统一改成 `8788` 与后端对齐；这位同学抄了旧值。
- 【修法】把前端环境变量的端口改成与后端实际端口一致：
  ```bash
  # frontend/.env
  VITE_API_BASE=http://localhost:8788
  ```
  改完重启前端即可。更省心的做法是别手动分起、直接用 `./run.sh`：它会自动扫空闲端口、把真实后端地址通过 `VITE_API_BASE` 注入前端，根本不会出现端口对不上。
- 【一句话总结】手动单起前端时，`frontend/.env` 的 `VITE_API_BASE` 端口必须和后端实际端口一致（默认 8788）；拿不准就用 `./run.sh` 让它替你对齐端口。
  <!--src:A; ref:code:frontend/.env.example; backend/src/server.ts; AGENTS.md 常见故障-->

## 五、面试自测（本阶段技术点常问题）

> 每题给：考察点 · 答题要点 · 一层追问。答案已写全，可自包含背诵。
> 说明：以下题目按 2026 年 AI 应用 / Agent 工程岗真实高频方向校准，考点集中在 AGENTS.md 部署规范、多 Agent 编排、权限分流、双引擎设计、SSE 与安全边界。

**面试 1｜AGENTS.md 是什么？它和 README.md 有什么分工？**
- 考察点：对「给 AI Agent 读的操作手册」这一开放标准的理解。
- 答题要点：AGENTS.md 是给 AI 编程 Agent（Claude Code / Codex / Cursor 等）读的操作手册，特点是命令优先、精确到 flag、少讲故事，让 Agent 能自动完成环境检查 → 要凭证 → 安装配置 → 启动 → 自检。README.md 是给人读的产品与上手说明。两者内容对齐但受众不同；小慧还配了 `CLAUDE.md`，内容只有一行 `@AGENTS.md`，让 Claude Code 转去读 AGENTS.md。
- 追问：「为什么把给 Agent 的手册单独拆一个文件，而不都塞进 README？」，因为 Agent 需要的是可直接执行的命令与验证标准，人需要的是背景与产品说明；拆开后 Agent 读起来歧义少、执行更稳，人读 README 也不被一堆命令淹没。
  <!--src:A; ref:code:AGENTS.md; CLAUDE.md; README.md-->

**面试 2｜小慧的「双引擎 mock / real」是怎么设计的？为什么默认 mock？**
- 考察点：演示系统在「课堂可靠」和「真实接入」之间的取舍。
- 答题要点：默认 `mock` 模式回放 `backend/data/*.json` 里录得的脱敏企业数据，零外部依赖、课堂直播不翻车；配置就绪后可切 `real` 模式真实 spawn OpenClaw agent。切换看 `BRAIN_MODE`，且每次动作调用时 `useReal()` 复核 `openclawAvailable()`（`~/.openclaw-hr` 目录 + `env.sh` 都在）。real 没就绪会自动降级 mock。默认 mock 是为了让任何人零配置就能看到完整链路。
- 追问：「real 没配好时，用户会不会以为自己成功切到 real 了？」，不会，`run.sh` 会打印降级提示，`/api/health` 返回的 `mode` 仍是 `mock`，同一个字段就能看出当前真实引擎。
  <!--src:A; ref:code:backend/src/openclaw.ts; backend/src/server.ts; run.sh-->

**面试 3｜这个系统的「三档权限分流」是怎么实现的？依据是什么？**
- 考察点：权限模型与合规意识。
- 答题要点：三档身份是普通员工（staff）/ 部门负责人（lead）/ HR 主管（hr）。每条任务带一个允许身份名单，判定就是「当前身份在不在这条任务的允许名单里」，命中放行、不命中拦截并提示可切换的身份。敏感操作名单最窄，比如全公司花名册导出和 HR 月报只允许 HR 主管，依据是《个人信息保护法》最小必要原则；政策自助问答三档都允许。
- 追问：「这套三档身份能防真实的越权访问吗？」，不能，它是前端可自由切换的权限演示开关，项目没有注册 / 登录 / 会话鉴权，属于教学演示，不是生产鉴权。
  <!--src:A; ref:code:frontend/src/modules/RouterConsole.tsx; docs/PRD.md 第5章-->

**面试 4｜「总控 Agent」在这个多 Agent 系统里到底干什么？**
- 考察点：对调度式多 Agent 架构里「路由者」角色的理解。
- 答题要点：总控 Agent 自己不办具体业务，只做三件事：判定领域 → 指派给对应职能子 Agent → 汇总结果回流。系统一共 6 个 Agent（1 个总控 + 招聘 / 入职 / 培训 / 绩效 / 员工关系 5 个职能子 Agent），五大职能各管一摊，对外合计表述 21 项业务能力。用户只面对一个统一入口说一句话，路由和分权交给总控。
- 追问：「总控判定领域后，权限校验是在总控这层做还是子 Agent 那层？」，在调度这层做：判定领域和指派之后紧接着按当前身份的允许名单校验，拦下来的请求根本不会真的落到子 Agent 去执行。
  <!--src:A; ref:code:frontend/src/modules/RouterConsole.tsx; frontend/src/lib/modules.ts-->

**面试 5｜用户随便打一句话，总控是怎么判断该归哪个职能的？判不出来怎么办？**
- 考察点：意图路由的实现与「不确定时的行为」。
- 答题要点：自由输入走一套「业务动作 + 业务对象」的关键词规则（`classify()`）：命中「花名册 / 导出 / 全员 / 月报」归员工关系且限 HR 主管，命中「简历 / 筛 / 评分 / 面试」归招聘，命中「入职 / 报到 / 审批」归入职，「培训 / 物料 / PPT」归培训，「绩效 / 360 / 反馈」归绩效，「年假 / 报销 / 政策」归政策问答。都不命中就不猜，返回澄清，反问用户想干嘛。预置任务则直接读后端登记好的路由数据。
- 追问：「为什么判不出领域时选择反问，而不是随便挑一个最像的？」，因为猜错会把敏感操作路由到错误职能、甚至触发不该有的权限判定；宁可多问一句澄清，也不赌一个可能错的领域。
  <!--src:A; ref:code:frontend/src/modules/RouterConsole.tsx classify-->

**面试 6｜前端那条「链路在一步步跑」的动画，是真流式还是假动画？怎么做的？**
- 考察点：SSE 流式与前端逐步揭示。
- 答题要点：是真的服务端推送。后端 `GET /api/:scenario/:action/stream` 用 SSE，把录得结果里的 `steps[]` 每 500 毫秒推一条 `event: step`，末尾推一条 `event: done`。前端 `streamAction` 用 `EventSource` 监听 `step` / `done` 事件，逐条揭示四步时间线（判定领域 → 指派 → 权限校验 → 结果）。如果后端 1.8 秒还没进展，前端就回退到本地分步揭示，保证观感不卡。
- 追问：「后端根本没起时，这个动画还能动吗？」，能，前端有回退：流式无响应就走本地 `localReveal` 定时逐步显示，甚至场景数据也会回退到前端内置数据，所以断网也能演示。
  <!--src:A; ref:code:backend/src/server.ts stream; frontend/src/lib/api.ts streamAction-->

**面试 7｜real 模式要 spawn 一个外部命令，怎么避免命令注入和互相抢占？**
- 考察点：spawn 外部进程的安全与并发控制。
- 答题要点：real 模式经 `bash -lc` 先 source `env.sh` 注入密钥、再调 `openclaw agent --agent <id> -m <message>`。安全上：agent id 来自数据文件、是受控常量，不来自用户输入；用户消息经 `JSON.stringify` 转义后才拼进命令。并发上：用一个全局串行队列，一次只跑一个 agent，避免多个请求抢同一 session；单次调用 90 秒超时就 SIGKILL 杀掉。
- 追问：「如果 openclaw 这个可执行文件根本没装，会怎样？」，spawn 触发 `error`，返回一句可读提示「无法启动 openclaw：请确认已安装并在 PATH 中」，不会把整个后端搞崩。
  <!--src:A; ref:code:backend/src/openclaw.ts runNow-->

**面试 8｜素材库能按文件名读文档原文，怎么防止有人用 `../` 读到目录外的文件？**
- 考察点：路径穿越（directory traversal）防护。
- 答题要点：`GET /api/doc/:name` 先用 `basename` 把传入的文件名归一化（剥掉任何路径部分），再拼到固定的 docs 目录下；然后双重校验 `fp.startsWith(DOCS_DIR)` 且文件确实存在，越界或不存在一律返回 404。这样即便有人传 `../../etc/passwd`，`basename` 也只留下最后一段文件名，落不到目录外。
- 追问：「只用 `basename` 够不够，为什么还要再判一次 `startsWith`？」，纵深防御：`basename` 已经能挡掉大部分穿越，再加前缀校验是兜底，万一某个环节归一化不彻底，`startsWith` 这道也能把落到目录外的路径拦下来。
  <!--src:A; ref:code:backend/src/server.ts /api/doc-->

**面试 9｜这个后端没有数据库，数据放哪、怎么加载的？这样有什么代价？**
- 考察点：无数据库演示项目的数据层设计。
- 答题要点：数据就是 `backend/data/*.json` 场景文件（六职能 + library 共 7 个）加 `backend/data/docs/` 下的脱敏文档（42 份，含 28 份简历）。加载走数据仓 `store.ts`：按场景名读对应 JSON、解析出 overview 和 actions，并用一个内存 Map 做缓存，同一场景只读盘一次。代价是数据是录得的、只读回放，不做真实落库，也没有并发写、事务这些数据库能力，但对课堂演示足够且零外部依赖。
- 追问：「数据加了缓存，改了 JSON 文件为什么不生效？」，因为首次加载后结果进了内存缓存，后续直接返回缓存；改了数据文件要重启后端才会重新读盘。
  <!--src:A; ref:code:backend/src/services/store.ts; docs/PRD.md 第11章-->

**面试 10｜让你验收一次「Agent 部署」，你会怎么证明它真的部署成功了，而不是 Agent 嘴上说成功？**
- 考察点：把「自检清单」变成可复现证据的工程习惯。
- 答题要点：不听 Agent 自述，逐项跑 AGENTS.md 的「部署完成的验证标准」拿证据：`curl /api/health` 看 `ok:true` 和 `mode`；`curl /api/recruitment` 看返回非空；浏览器打开前端进 `/app` 看六职能都在；在总控台用普通员工发「导出全公司花名册」看被拦、切 HR 主管看放行。每条都截图，再手写一页复盘，记下至少一个自己排掉的错误。这样才叫「你验收它」，而不是 Agent 说了算。
- 追问：「如果 Agent 报告全部通过，但你 curl health 拿到的是 `mode:"real"` 而你根本没配 OpenClaw，说明什么？」，说明环境和你以为的不一致（要么真配了 profile+env.sh、要么判定被别的因素影响），得停下来核对 `~/.openclaw-hr` 和 `env.sh` 到底在不在，别急着签收。
  <!--src:A; ref:code:AGENTS.md 部署完成的验证标准; backend/src/server.ts-->

## 八、落地对照（学完这阶段能接的真实小活）

> 都是这阶段能力就能接的活儿，描述自包含。它们是你作品集和「超级个体」现金流的第一步。

1. **帮别人把带 AGENTS.md 的开源项目在他电脑上部署跑通。**
   很多人有「想用某个 AI 项目但装不明白」的需求。你会让 Agent 读 AGENTS.md、查环境、要凭证、一键起，再逐项过验证标准交付「能打开的地址 + 自检截图」。默认走 mock / 零外部依赖那条最稳，交付成功率高。

2. **给小团队搭一个「一句话派活」的内部演示台。**
   小慧这套「自然语言进 → 判领域 → 分权限 → 结果回流」的形态，可以裁剪成任何部门的内部工具原型（如「一句话查制度」）。你已经会改数据文件、配三档权限、看懂前后端怎么通信，正好接这类演示型需求。

3. **做「AI 项目部署 + 验收」的陪跑服务。**
   面向不敢自己动手的人：你带着他把一个工业项目部署起来，逐项过验收标准，并教他怎么用 `/api/health` 这类自检手段确认真的跑通了，而不是 Agent 嘴上说通了。交付物是一份可复现的部署与自检记录。

4. **给一个只读回放的演示系统做数据脱敏与替换。**
   小慧的数据就是 `backend/data/*.json` 加 docs 里的脱敏文档。你懂这套「录得数据回放」的结构，可以帮别人把演示系统里的真实数据换成脱敏样例，做一个能对外展示、又不泄露真实信息的 Demo 版本。

5. **把一个跑通的项目整理成可复用的部署手册。**
   你自己部署一遍后，能照 AGENTS.md 的写法，给别人的项目补一份「命令优先、带验证标准」的部署清单。这本身就是一单可交付的文档活，也顺带把项目变成你作品集里能讲清楚的一项。

# 企业落地 / 一人公司 · 学习路径（人读版）

> 选对一个业务场景，用 Agent 把它真跑到生产，并留下能复制到第二场景的方法。
>
> **适合谁**：手里有明确业务场景、要把它真跑到生产的人——创业老板 / 独立开发者 / 企业内部落地推动者。你要的不是学全栈，而是最短路径让一个场景上线可用。
>
> **不适合 / 改走哪条**：
> - 零编程、想先建立信心的探索者 → 改走 **zero-to-builder**（先补工具链与第一个作品）
> - 想系统吃透 Agent 框架与原理的工程师 → 改走 **engineer-transform**（从 Stage 4 框架进）
> - 只想听原理不落地的人 → 本路径每阶段都要交可运行产物；每周 <5h 会拖到部署站掉队，建议先攒到每周 8h 再开

## 入门自测（定你的入口站，用站号）

| 你的情况 | 入口 |
|---|---|
| 还不能用 Cursor/Claude Code 让 AI 改一次代码并提交 | 从 **A1** 进 |
| 已能改码提交、但没装课程全家桶 | A1 快速过，重点做 A1 深潜验收；到 **A2** |
| 全家桶已装、还没想清落地哪个场景 | 直接进 **B1**（本路径最关键一站，别跳） |
| 场景已想清、数据也评估过 | B1 加速，直奔 **B2** 打样 |
| 已有场景本机能 demo、只差上线 | 从 **C1** 进，前面作回顾 |

## 承诺（留余量口径）

按推荐节奏（每周约 10h）你可以产出：**选型决策矩阵**、**选定场景生产可用 MVP**、**接口化+容器化上线版本**、**《上线验收报告》**、**可复制方法包**。
各产物工时区间：场景打样 8-14h、接口与容器上线 6-11h、生产化收口 5-9h。**不承诺固定周数必得**——场景复杂度与数据就绪度会让总时长浮动。

## 场景选型速查（B1 决策节点用）

| 场景 | 什么时候选它 | 打样脚手架（课程项目） | 对应课件 |
|---|---|---|---|
| **知识库** 问答/检索/企业大脑 | 有大量文档/FAQ，诉求是「问得到、查得准」 | advanced-rag / ff-companybrain | Part 3 / 01 工业级知识库搭建项目组 |
| **流程** 业务流程全功能复刻 | 有重复人工流程（文档审核/合同初审），诉求是「端到端替人跑」 | ai-document-review | Part 3 / 02 任意业务流程全功能复刻 |
| **运维** SRE 智能助手 | 盯系统稳定性，诉求是「告警聚合、事故定位与处置提效」 | ff-sre-incidentops | Part 1 / 05 AI运维&SRE智能助手 |

> **选型铁律**：数据就绪度优先，数据没到位的场景无论多诱人都后置，先落地数据最全的那个。

## 到站验收勾选清单（进度=打勾）

### 阶段 A · 快速接入
- [ ] **A1** 在 ff-claude-code-web 工作台亲手指挥 Claude Code 完成一次改动并提交（工作台可见产物 + git 有提交）
- [ ] **A1 深潜专属** 关掉 Agent 代答，自己对着代码口述前端/后端/Agent 三层各干什么 ← 徽章闸门
- [ ] **A2** 全家桶装入 ~/.claude/skills，对照清单逐项核对已加载能力，截图为产物存档
- [ ] **A2 预告** 已申请 DeepSeek 与阿里云百炼各一个 Key（下一阶段打样用）

### 阶段 B · 场景选型与打样
- [ ] **B1 深潜专属** 手写《场景选型决策矩阵》：候选场景 × 数据就绪度/投入产出/落地风险/可复制性，圈出唯一选定结论（存档为作品集第一件）← 徽章闸门
- [ ] **B1 预告** 按选定场景备好该场景外部依赖（向量库Key/流程样例数据/告警日志样本）
- [ ] **B2 子验收①** 选定场景项目本机原样跑通（看到默认 demo）
- [ ] **B2 子验收②** 换成你自己的业务数据跑一次，结果符合预期
- [ ] **B2 子验收③** MVP 能从头到尾跑通，端到端演示一次核心业务动作（录屏/截图）
- [ ] **B2** 对照选定项目 AGENTS.md 本机运行相关条目逐项打勾
- [ ] **B2 预告** 装好 Docker Desktop、备好可 SSH 云服务器（C 阶段上线用）

### 阶段 C · 部署上线
- [ ] **C1 子验收** 核心能力封装成接口端点 → 可被 curl 调用 → 有错误处理与配置外置
- [ ] **C1 深潜专属** 亲手 curl 通接口（不靠 Agent 代跑）+ 手绘一张请求→模型→响应的数据流架构图 ← 徽章闸门
- [ ] **C1 预告** 确认 Docker Desktop 就绪（可选装 minikube/kind 练集群）
- [ ] **C2 子验收** docker build 出镜像 → docker compose up 一键起 → curl 通接口
- [ ] **C2** 容器化交付产物（镜像/compose 文件）存档

### 阶段 D · 生产化收口
- [ ] **D1** 搭贴合业务的评估集（带标注答案）→ 跑出指标基线 → 一轮优化，前后对比表存档（用数值不用「感觉」）
- [ ] **D2** 给 Agent 加驾驭约束（工具白名单 + 输出校验 + 失败兜底）→ 越界/异常用例验证被约束住
- [ ] **D3 深潜专属** 手写《上线验收报告》，逐项核对选定项目 AGENTS.md「部署完成的验证标准」并逐项签字（关掉 Agent 代打勾），每项附证据 ← 徽章闸门
- [ ] **D4 支线** 复用选型矩阵+部署清单+验收模板跑第二场景，记录工时对比证明方法可复制

## 复习锚点（每站要素 · 本站技能在哪站被复检）

| 学到的技能（站） | 后续在哪复检 |
|---|---|
| A1 工作台派活 | B2 打样派活、D3 验收再跑一遍 |
| A2 全家桶 | B2/C1/C2/D1/D2 各站快车道都依赖它已装 |
| B1 选型矩阵 | D3 回看选型假设是否成立、D4 复制时复用 |
| B2 场景打样 | C1 接口化、D1 评估、D3 验收核对同一份 AGENTS.md |
| C1 接口化 | C2 塞进容器、D3 核对接口可用性 |
| C2 容器化 | D3 核对可一键复现、D4 复用容器模板 |
| D1 评估 / D2 驾驭 | D3 验收报告写入指标实测值与约束结论 |

## 并轨点

- **在 B 阶段**：打样时若要深挖某框架/RAG 原理，可并入 **engineer-transform**（Stage 4 起点），把选定场景当练手项目继续往工业级打。

## 终点之后

- **Part 4. 百万用户级项目开发实战** —— 当场景要扛真实规模（高并发/高可用/成本优化）时进阶，在 D3 上线验收基线上加压测与高可用验收。
- **把 D4 第二场景扩成场景矩阵** —— 多场景跑通后，把通用件（接口层/容器模板/评估框架/驾驭约束）抽成你自己的内部平台，「一人公司」→「一人平台」。

# 模型权重原理及显存需求计算

模型 = 架构 + 权重


权重的本质
神经元之间的链接强度 被成为权重

误区：文件越大 = 越厉害？ 
Qwen3-8B FP16，size16GB，参数量8B
Qwen3-32B INT4，size16GB，参数量32B， 强大4倍
文件大小 = 参数量 x 精度（FP16、INT4）
判断能力，只看参数量，不看文件大小

两种“用脑方式”：Dense vs MoE
Dense（稠密） : 全部参数应用计算，参数量计算量很大
MoE：混合专家模型，不会用全部的参数计算量，只用其中的一部分参数回答
- 比如 DeepSeek-V3，671B， 总专家256个

显存估算速算法
静态显存 =（ 参数量（B）x 每参数比特数）  / 8

真实显存 = 静态显存 +  KV Cache动态缓存

# 大模型量化技术介绍GGUF、AWQ格式选型

在不明显降低智力的情况，让模型变快
- FP32：32-bit,4字节， 需要280GB显存，精度100%
- FP16/B16：16-bit,2字节，半精度浮点，140GB显存，精度99.9%
- INT8：8-bit，1字节，8位整数，70GB显存，90%精度
- INT4：4-bit，0.5字节，35GB显存， 85%-90%的精度保留


PPL 困惑度
量化后的模型还聪明吗？用数字衡量量化质量的黄金标准
PPL越低越好


量化格式详解
- GGUF：llama.cpp出品，显存不足，mac用户，CPU推理，一键部署
- AWQ：激活感知量化，显存充足，追求速速，生产环境，vLLM部署
- GPTQ：逐渐被AWQ取代

K-Quants 混合精度：GGUF的核心竞争力：关键层用高精度，普通层用低精度
